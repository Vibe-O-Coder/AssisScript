## Objetivo e antes/depois

Os recursos do exemplo anterior usavam posições mutáveis e IDs que nunca eram
reutilizados na execução. Isso não demonstrava reciclagem sem replay.
Agora `std/arena.assis`, escrito em AssisScript, mantém slots estáveis e valida
categoria, instância, índice e geração antes de acessar o recurso. Remover um
recurso invalida sua identidade sem alterar as demais; reutilizar o slot não
faz um identificador antigo apontar ao novo objeto.

O exemplo e os testes compilam com o compilador atual, sem mudar lexer,
tipagem, ownership, IR, sintaxe, ABI ou runtime. As abstrações existentes
atenderam à unidade. Uma tentativa inicial de retornar null como borrow foi
recusada pelo contrato atual de origem de vida; a API usa contains/remove
recuperáveis e precondição explícita para get/get_mut. Não se alterou a
linguagem para contornar essa regra.

## Implementação e decisões

- Handle Copy com quatro campos de identidade; Slot próprio em OwnedArray.
  A lista livre mantém índices, sem ponteiros externos ou troca de posições.
- Inserção consome recurso e retorna variante própria: Inserted(handle) ou
  Rejected(código,own recurso). Rejeição por fechamento/quota preserva posse.
- Remoção devolve Missing ou Removed(own recurso); tentativa repetida não
  destrói novamente. get/get_mut emprestam pela vida da arena inteira.
- Geração nunca faz wrap. O slot no limite é aposentado. O limite configurável
  permite provar esgotamento com valores pequenos pelo mesmo caminho de código.
- close é idempotente; reset exige instância estritamente maior, invalida todos
  os handles anteriores e reabre vazia. O host atribui instâncias únicas no
  domínio; instância máxima encerrada não é reutilizada.
- A quota inclui slots livres/aposentados. Ela não é alocação fallível: OOM,
  inclusive alocação das variantes de resultado, continua fatal.

Handle é identidade local inspecionável, não segredo/capacidade de autorização.
Não substitui origem, concessão ou registro opaco da API de página futura.
Uma identidade viva inteiramente reproduzida não pode ser distinguida do seu
original por essa arena. A unicidade de instância/categoria entre arenas é
responsabilidade do host confiável. Não há autoridade nova para conteúdo.

get/get_mut inválidos encerram com status 70; contains e remove recusam antes
de indexar e permitem tratar entrada expirada sem abortar. A arena não implementa
relações ordenadas de filhos, árvore HTDL, snapshots, callbacks, IPC ou threads.
Essas obrigações impedem promover E02-02 além do subconjunto de nível 2.

## Testes e evidências desta unidade

Windows x64/PowerShell/Python 3.14 e Linux x64/Ubuntu/WSL2. Os compiladores
foram reconstruídos nesta sessão durante a unidade M0 de coleções; nenhum
fonte do compilador usado pelos candidatos mudou desde aquele build.
Os hashes foram novamente conferidos, e cada programa de arena foi compilado
e executado nesta unidade, com os novos fontes da biblioteca.

```powershell
$env:ASSIS_BIN=(Resolve-Path build/assis-m0-owned.exe).Path
python tools/validate-arena.py --output build/arena-validation/windows-x64.json
python tools/test-portability.py --expect-host x86_64 --output build/arena-validation/windows-x64-portability.json
```

```sh
ASSIS_BIN="$PWD/build/assis-m0-owned-linux" python3 tools/validate-arena.py --output build/arena-validation/linux-x64.json
ASSIS_BIN="$PWD/build/assis-m0-owned-linux" python3 tools/test-portability.py --expect-host x86_64 --output build/arena-validation/linux-x64-portability.json
```

**81/81 métodos por host passaram, sem dispensas, retorno 0**: arena (13),
owned-mutation (12), move-enums (10), ownership-functions (26), managed-classes
(9), english-api (4), complete-ir (7). São execuções desta revisão de biblioteca,
sem reaproveitar os resultados anteriores. O resumo JSON registra duração,
comandos, plataforma/Python e hashes de fontes/candidatos/logs.

Os 13 métodos da arena cobrem 180 operações contra modelo Python de objetos
lógicos que não prevê slots/lista livre, recursos aninhados, mutação, remoção,
reset, rejeição de categoria/instância/geração/índice, INT64_MAX, geração
esgotada sem wrap, quota zero, 10.000 reciclagens com um único slot, empréstimos,
escape, buffers e destruição única após rejeição/remoção/reset/close.

A primeira rodada encontrou duas suposições inválidas do teste: init manual é
rejeitado na compilação (não é trap de runtime), e literal null não satisfaz
parâmetro own de buffer. Os testes foram corrigidos para os contratos reais;
nenhum comportamento do compilador foi relaxado. A rodada final passou completa.

Portabilidade: **20/20 casos por host**, incluindo arena nos dois modos,
assinaturas/arquiteturas PE/ELF/Mach-O dos cinco destinos conferidas por leitor
independente e execução somente do destino x64 local. O teste da arena exige
IR com astFallbacks=0. O exemplo produz exatamente `42\n` e debug sem vazamentos.
